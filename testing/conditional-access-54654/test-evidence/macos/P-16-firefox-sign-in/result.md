# macOS P-16: Firefox uses the OS certificate
- **Date:** 2026-10-08 (UTC). Firefox was installed by Fleet from the Fleet-maintained app `firefox/darwin` (policy automation "Firefox installed (macOS)", software install at 2026-10-07 12:42 UTC, `fleetctl` shows it in the host's software list). It was not running before the test.
- `01-firefox-after-open.png`: Firefox window only. Firefox offers the renewed certificate (serial `...2B:4D`, valid Oct 8 05:38:40 to Oct 9 10:09:40 UTC, issued by Fleet Lab CA Intermediate CA) and shows **Stored on: OS Client Cert Token**. So Firefox reads the macOS keychain certificate without any import.
- Firefox has no auto-select for a single certificate here: the user chooses OK once ("Remember this decision: For this session").
- **First attempt (`02-firefox-after-ok.png`):** the sign-in ended at `error=access_denied`, "Authentication failed." That is the same message PingFederate gives when no certificate is sent (see Linux P-11). So Firefox did not present the certificate. The likely cause is that the keychain access to the key was not allowed (or "Don't send a certificate" was chosen). Retry below.

## Result: **PASS** (third attempt, after a clean Firefox start)
- **Attempts 1 and 2** (`02`, `04`) ended at `access_denied` "Authentication failed". PingFederate logged `[X509000] No Client Certificate was presented.` for both (`05-pingfederate-log-no-certificate-presented.txt`). Attempt 1 waited on the dialog for 5 minutes and ended with no certificate sent; attempt 2 failed instantly because Firefox remembers a "no certificate" answer for the session.
- **Attempt 3** (Firefox quit and restarted; OK on the dialog; Always Allow on the keychain prompt): sign-in succeeded and returned an authorization code (`06-firefox-fresh-dialog.png` shows the dialog, `07-firefox-result.png` the callback, with the code masked; `08-pingfederate-audit-success.txt` shows `success` for the `x509lab` adapter).
- **Guide notes:** (1) Firefox needs a one-time keychain "Always Allow" like Safari and Chrome; denying it silently ends as "Authentication failed", which looks like a missing certificate. (2) After a wrong answer, Firefox must be restarted before it asks again.
