## 3. Code at `main`
**How the PIN flow works:**
1. `tpm_pin_config_verify` runs only when the fleet has disk encryption on and a PIN required, C: is protected, and there's no PIN protector. It sends PIN = 2 (the other dropdowns default to 2), minimum length 6, enhanced PIN, and standard users allowed to change the PIN. It sends this only if one of these holds:
   - `UseTPMPIN` is neither 1 nor 2
   - `UseEnhancedPin` isn't 1
   - `MinimumPIN` is set to something other than 6
   - `DisallowStandardUserPINReset` is set to something other than 0
2. `ActionRequiredCreatePIN` is shown only when the PIN is missing, protection is on, and a boot protector exists (`server/datastore/mysql/microsoft_mdm.go:2403`).
3. fleetd advertises the capability `windows_bitlocker_pin`. The server stores it and exposes `fleetd_can_set_pin` on `GET /api/v1/fleet/device/:token`.
4. The user posts the PIN to `POST /api/v1/fleet/device/{token}/disk_encryption_pin`. The server checks it's 6–20 printable ASCII characters, checks again that the host needs a PIN, encrypts it and queues it. If fleetd is too old: "Fleet's agent on this host is too old to set a BitLocker PIN. Update fleetd and try again."
5. The orbit config carries `bitlocker_pin_request_pending`. fleetd collects the PIN once from `/api/fleet/orbit/disk_encryption_pin/details`, then `setTPMAndPINProtector` (`orbit/pkg/bitlocker/bitlocker_management.go:242`) runs:
   - requires C: fully encrypted, protection on, and no existing PIN protector
   - calls WMI `ProtectKeyWithTPMAndPIN`
   - deletes the TPM-only protectors, and rolls back if that fails
   - reports to `.../result`
6. **Error mapping:** these codes get a specific message: 0x80310068, 0x8031009A, 0x803100CC, 0x80310031, 0x80284008, 0x80310000, 0x80310030, 0x80310023. Anything else becomes "Windows couldn't add the PIN (error 0x…)". That includes a policy that disallows a PIN, and 0x803100B5/B6 ("no pre-boot keyboard"), if WMI returns them.
7. **Nothing handles Modern Standby, HSTI, InstantGo or slates**, and no tests mention them. `EnablePrebootInputProtectorsOnSlates` appears only in `website/profile-generator/schema/windows-csp-nodes.json`, and Fleet never sends it.
8. **Untested, from reading the code:** a custom profile that keeps the four values in step 1 wouldn't trigger a re-send. The relax query fires only when there's no TPM-family or startup-key protector and `UseTPM` = 0. So a custom profile might coexist with Fleet's disk encryption on, despite the guide's warning.
