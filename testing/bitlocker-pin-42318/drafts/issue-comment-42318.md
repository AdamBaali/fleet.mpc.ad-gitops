**Update (2026-10-16):** lab results on Fleet 4.93.0 for the customer's ask (an *enforced* 6-digit PIN on Windows, **no Fleet Desktop**, non-admin users, or a clear "not supported" statement). Evidence, profiles and scripts: [testing/bitlocker-pin-42318](https://github.com/AdamBaali/fleet.mpc.ad-gitops/tree/main/testing/bitlocker-pin-42318) ([EVIDENCE.md](https://github.com/AdamBaali/fleet.mpc.ad-gitops/blob/main/testing/bitlocker-pin-42318/EVIDENCE.md) has the screenshots).

**Results**
- **No self-service PIN for non-admin users without Fleet Desktop.** With Fleet's "Require BitLocker PIN", and also with a custom profile that sets PIN to *Required* (other methods disallowed), nothing prompts the user and the TPM-only protector stays. A standard user who opens Manage BitLocker → "Change how drive is unlocked at startup" gets a UAC prompt for **admin credentials**.
- **Works today if IT sets the PIN from Fleet.** A Fleet script (SYSTEM via fleetd) running `Add-BitLockerKeyProtector -MountPoint C: -TpmAndPinProtector` on the already-encrypted drive replaced TPM-only with TPM+PIN; Fleet showed disk encryption **Verified** and a PIN policy went fail → pass. The standard user then gets **"Change PIN" with no admin prompt** (old + new PIN). After 4–5 wrong old PINs Windows disables changes until an admin resets the PIN.
- **Why some devices offer "only USB" and no PIN option: Windows thinks they're tablets.** Before Windows loads there's no on-screen keyboard, so on any device Windows classifies as a tablet ("Slate" platform role), BitLocker hides every startup method that needs typing (PIN or password) and leaves only the USB key. Windows takes that classification from the device firmware, not from whether a keyboard is attached, so normal laptops can be affected too (Microsoft Q&A shows a clamshell Surface Laptop 7 reporting "Slate"). Microsoft's override is `SystemDrivesEnablePrebootInputProtectorsOnSlates`, which **Fleet's "Require BitLocker PIN" doesn't send**. Tested: a VM made to report itself as a tablet refused PIN/password methods with `0x803100B5` "No pre-boot keyboard detected"; a one-setting Fleet profile ([D2](https://github.com/AdamBaali/fleet.mpc.ad-gitops/blob/main/testing/bitlocker-pin-42318/profiles/D2%20-%20BitLocker%20preboot%20input%20on%20slates%20only.xml)) was **Verified** and removed the block; the same VM reporting itself as a desktop never had the block. This is also why the bug didn't reproduce on a desktop-class test device.
- **Fleet's payload itself is fine on a desktop-class device:** an admin saw "Enter a PIN" and added one. Leaving the other methods at Allow is not what hides it.
- **Fleet 4.93's My device PIN form** (#49133) removes the admin step but needs Fleet Desktop and fleetd 1.62 (not released; stable/edge are 1.61.0).

**On the open questions**
- **Script (Victor/Marko, Apr):** a registry cleanup script isn't needed and wouldn't stick (`deviceenroller` reverts CSP-owned values). The policy half works: `SELECT 1 FROM bitlocker_key_protectors WHERE drive_letter = 'C:' AND key_protector_type IN (4, 6);` fails on hosts without a PIN.
- **"Require only works on unencrypted hosts" (Apr 20–21):** an admin added a PIN to an already-encrypted drive with PIN Required and the other methods Disallowed. Required doesn't *force* a PIN, but doesn't block one.
- **"Lock after 3 failed attempts":** no setting does this. At startup Windows already stops guessing: after 5 wrong PINs, the 6th sent the device to BitLocker recovery (recovery key escrowed in Fleet). The TPM lockout policy can be sent by a Fleet profile (`ADMX_TPM`, Verified) but only gives 32 failures / 2 h heal, and can't be undone without clearing the TPM.
- **Refetch stalls on physical devices:** not seen on the VM; not verified on hardware.

**Workaround today** (needs `mdm.enable_custom_disk_encryption`): keep Fleet's disk encryption on and let it encrypt first; add a custom profile with PIN = Required and the other methods Disallowed, min PIN 6, enhanced PIN ([C](https://github.com/AdamBaali/fleet.mpc.ad-gitops/blob/main/testing/bitlocker-pin-42318/profiles/C%20-%20BitLocker%20PIN%20required%2C%20others%20disallowed.xml)); set the initial PIN with a Fleet script ([example](https://github.com/AdamBaali/fleet.mpc.ad-gitops/blob/main/testing/bitlocker-pin-42318/tests/add-pin-random.ps1), random PIN); report with the policy above. On devices that only offer USB, also add D2 ([platform-role.ps1](https://github.com/AdamBaali/fleet.mpc.ad-gitops/blob/main/testing/bitlocker-pin-42318/tests/platform-role.ps1) run from Fleet lists which devices report "Slate"; `msinfo32` > Platform Role shows the same).

**Not verified:** refetch stalls on physical devices. (On the tablet VM the block and fix were shown with a startup password, as the VM has no usable TPM; Windows applies the same keyboard rule to PIN and password.)

1. Non-admin PIN without Fleet Desktop (or confirm #49133 covers it once fleetd 1.62 ships).
2. Send `SystemDrivesEnablePrebootInputProtectorsOnSlates` with "Require BitLocker PIN", so the PIN option isn't hidden on tablet-classified devices.
3. Docs PR #43915 says "Resolves #42318" and that the PIN can only be enforced on unencrypted hosts, which the lab contradicts; it shouldn't close this as is.
